# Лаборатория нестабильных порталов

Веб-приложение для смотрителя лаборатории. Оно показывает состояние магических порталов, помогает оценивать их риск, выполнять допустимые действия и отслеживать изменения в общем журнале и истории конкретного портала.

## Возможности

- список порталов и Summary по текущему состоянию;
- раскрываемые карточки с названием, кодом, destination world, energy, stability, creatures inside и status;
- countdown до collapse для активных порталов;
- числовой risk, risk level и recommended action;
- действия: стабилизация, закрытие, отправка наблюдателя, `questionable`, повторное открытие закрытого или схлопнувшегося портала;
- frontend-проверка доступности действий и backend-защита невозможных состояний;
- создание и удаление порталов;
- persistent Creature Bank с операциями `+` и `−`;
- общий Event Log и история конкретного экземпляра портала;
- локализация UTC timestamp в часовую зону браузера;
- отдельная вкладка AI Worklog.

## Архитектура

```text
React UI → FastAPI API → SQLite
```

**Frontend:** React, TypeScript, Vite.  
**Backend:** Python, FastAPI.  
**Persistence:** SQLite через SQLAlchemy.

Backend является источником истины для бизнес-правил, переходов состояний и проверки невозможных действий. Frontend дополнительно показывает доступность кнопок, но не заменяет backend-валидацию.

## Основные состояния

| Состояние | Смысл |
| --- | --- |
| `OPEN` | портал открыт и может работать до collapse; |
| `STABILIZED` | портал стабилизирован; |
| `OBSERVATION` | портал переведён под наблюдение; |
| `QUESTIONABLE` | портал помечен как требующий внимания; |
| `CLOSED` | портал закрыт оператором; |
| `COLLAPSED` | портал схлопнулся по истечении времени. |

Backend не разрешает логически невозможные переходы. Например, закрытый портал нельзя стабилизировать, наблюдателя нельзя отправить при критическом риске, а закрытие портала с существами требует подтверждения оператора.

## Расчёт риска

Формула находится в `backend/app/calculations.py`:

```python
instability = 100 - stability

energy_pressure = min(
    100,
    50 + abs(energy - 50),
)

time_pressure = max(
    0,
    min(100, 100 - minutes_remaining / 60 * 100),
)

risk = (
    0.45 * instability
    + 0.30 * energy_pressure
    + 0.25 * time_pressure
)
```

- `instability`: чем ниже стабильность, тем выше риск;
- `energy_pressure`: значение 50 считается оптимальным, отклонение в любую сторону повышает pressure;
- `time_pressure`: чем меньше времени до collapse, тем выше срочность;
- веса факторов: stability-related instability — 45%, energy — 30%, time — 25%.

`risk` — числовая оценка опасности, а `status` — состояние портала. Для `CLOSED` и `COLLAPSED` backend возвращает `risk: null` и `risk_level: null`: активный риск для этих состояний не отображается.

## Creature Bank

Общий запас существ хранится в SQLite и переживает перезагрузку страницы. При создании порталу может достаться случайное количество существ, но не больше доступного запаса. Если банк пуст, новые порталы создаются без существ — это ограничение текущей модели ресурса, не создание существ «из воздуха».

Кнопка `+` переводит одно свободное существо в портал только при наличии запаса. Кнопка `−` возвращает одно существо обратно и недоступна при нулевом количестве внутри портала. Backend не позволяет банку или порталу уйти в отрицательное значение.

## Event Log и история порталов

Все жизненные действия портала записываются в события. В приложении есть общий Event Log и история внутри раскрываемой карточки.

Время хранится backend в UTC с timezone-информацией и отображается frontend в локальной часовой зоне браузера, включая реальные секунды.

Для разделения поколений используется `portal_instance_id` — внутренний уникальный numeric ID экземпляра. Пользовательский `portal_code` может быть переиспользован: например, новый `P-002` не должен получить историю старого удалённого `P-002`. Событие удаления сохраняет `portal_code` и остаётся доступным в общем журнале даже после удаления портала.

## Запуск

### Prerequisites

- Python 3.12 или совместимая версия;
- Node.js и npm;
- установленные Python-зависимости FastAPI, Uvicorn, SQLAlchemy, pytest и httpx.

В репозитории нет `requirements.txt`, Docker-конфигурации или отдельного менеджера Python-зависимостей. В текущем окружении зависимости уже установлены.

### Backend

Из корня проекта:

```powershell
uvicorn backend.app.main:app --reload
```

Backend будет доступен на `http://127.0.0.1:8000`.

### Frontend

В отдельном терминале:

```powershell
cd frontend
npm install
npm run dev
```

Vite использует `http://127.0.0.1:5173` или следующий свободный порт.

### Проверки

```powershell
pytest

cd frontend
npm run lint
npm run build
```

## API

| Метод | Endpoint | Назначение |
| --- | --- | --- |
| `GET` | `/health` | проверка доступности backend; |
| `POST` | `/portals` | создание портала по имени и миру назначения; |
| `GET` | `/portals` | список порталов с текущими показателями; |
| `GET` | `/events` | общий журнал событий; |
| `POST` | `/portals/{code}/actions` | действия над порталом, включая управление существами и `delete`; |
| `GET` | `/creatures` | текущее количество свободных существ в банке. |

## Ограничения и дальнейшее развитие

Текущая версия рассчитана на локальный сценарий проверки и SQLite. Для production-развития потребовались бы:

- расширенная система управления существами;
- frontend automated tests;
- monitoring и structured logging;
- более детальная модель времени и аварийных состояний.
